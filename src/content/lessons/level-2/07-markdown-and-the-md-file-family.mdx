## Why this matters

One format shows up everywhere in this course: your notes, your prompts, [Project instructions](/lessons/level-2/06-projects-files-and-instructions/), README files, and later skill files. That format is **markdown**, and it's worth ten minutes now because it's the one way of writing structure that survives being copied between tools. Learn it once and your notes stop breaking when you paste them.

## What markdown is, and why plain text travels

Start with the problem markdown solves. A word processor stores your heading as *hidden formatting*: a font, size, and color locked inside that program's file. Copy it into a different tool and that hidden part gets lost or garbled, because the other tool doesn't speak the private format. The look was never in the text; it was in the file around it.

**Markdown takes the opposite approach.** It's **plain text**, just characters, with a few visible marks that *stand for* structure. A `#` at the start of a line means "heading." A `*` means "list item." Because the structure is ordinary characters, nothing is hidden, so nothing gets lost in the copy: any tool that reads text reads markdown. A file ending in **`.md`** is simply a markdown file.

See it with a real note. **Jun** keeps notes in a word processor with fancy fonts; when he pastes to Claude, headings turn to noise and a table collapses. His friend **Ola** keeps the same notes in plain text with simple marks, and everything pastes cleanly. Here's a piece of Jun's note as it arrives:

`Trip budget  FLIGHTS 420  HOTEL 310 (3 nights)  FOOD 150  TOTAL ? ... remember to check passport!!`

Claude sees only spacing and capital letters there, no structure, because the structure lived in fonts that didn't survive the paste. The same content in markdown carries its structure in the characters themselves:

```markdown
# Trip budget

| Item | Cost |
| --- | --- |
| Flights | 420 |
| Hotel (3 nights) | 310 |
| Food | 150 |
| **Total** | **880** |

**Remember to check passport.**
```

That's the whole idea: Ola's notes survive because the structure *is* the text.

<Callout variant="mistake" label="Common mistake">

Pasting from a word processor and assuming the headings, tables, and bold come along. They don't: that formatting lives in hidden fonts that Jun's paste left behind, so Claude sees only spacing and capitals. When structure matters, write it in visible marks (`#`, `*`, `**bold**`) rather than relying on how it looked in the other tool.

</Callout>

One more distinction: what you *type* versus what you *see*. The block above is **raw markdown**, the literal characters in the file. In a tool like Obsidian or a rendered preview, those same characters become a formatted heading and a visual table: the raw `#` and `|` disappear and you see bold text and grid lines instead. Claude reads the raw text, so structure written in visible marks survives either way. A word-processor file doesn't offer this choice: its formatting is always hidden, never raw text you can copy.

## The three marks that cover most work

You don't need all of markdown. Three marks handle most everyday notes:

- **Headings:** `#` for a big heading, `##` for a smaller one under it. One line, starts with the hash.
- **Lists and tables:** `*` or `1.` at the start of a line makes a list; `| a | b |` rows make a table (just text with pipes between columns).
- **Emphasis:** wrap a word in `**double asterisks**` to make it bold.

That's enough to give any note visible structure. The rest of markdown exists, but these three earn their keep first.

## The rule

<Callout variant="framework" label="Plain Text, Light Structure">

1. `#` and `##` for headings
2. `*` or `1.` for lists, and `| a | b |` rows for tables
3. `**word**` for emphasis

Name files by topic, like `style-guide.md`, and keep **one topic per file**. Markdown shows up everywhere ahead: your notes, your prompts, Project instructions, README files, and skill files.

</Callout>
