Level 3 · Lessons 15 to 20

Building with Claude

Stepping out of the chat box into Claude Code: the terminal and Git, safe first sessions, the filesystem as context, tools and untrusted input, reusable skills, and testing a workflow before you trust it.

Start Level 3→See the course map

Level 3

  • →Use the filesystem as context
  • →Keep tool access small, treat input as untrusted

Start Level 3→

After this level you can…

  • ✓Open a terminal, move around safely, and use Git to undo a mistake.
  • ✓Launch Claude Code in a practice project, read its proposed changes, and undo them.
  • ✓Organize files so Claude can find what it needs without you pasting anything.
  • ✓Use tools for exact work, keep tool access small, and treat anything Claude reads from the outside as untrusted.
  • ✓Write and place a reusable skill file, and build a small eval that catches failures before real work does.

Level 3 lessons

  1. 15Bridge: the terminal, paths, and GitBridgeExerciseThe terminal is just how you tell your computer where you are and what to do, and Git gives you an undo you can trust before you ever open Claude Code.8 min→
  2. 16Claude Code: your first safe sessionExerciseClaude Code is safe to start when you keep it in a small practice folder, run a mode that asks before acting, read every proposed change, and lean on Git as your undo.6 min→
  3. 17Filesystem as contextConceptOnce Claude can read your folders, the way you name and arrange files becomes the context, so a clear map lets it find what it needs without you pasting anything.4 min→
  4. 18Tools, scripts, MCP, and untrusted inputConceptTools let Claude do exact work like math and actions, but exact is not the same as correct, so keep each tool's reach small and treat anything Claude reads from the outside as untrusted.9 min→
  5. 19Reusable skillsExerciseA skill is a small file that captures how you do a repeated task, so once you write it down and test it, Claude stops needing the same thing re-explained every time.6 min→
  6. 20Verification and evalsConceptOne good try lies to you, so build a small deliberate test set and run it against a workflow before you rely on it, making failures show up in testing instead of in real work.7 min→
