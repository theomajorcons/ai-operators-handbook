A practical field guide

The AI Operator’s Handbook

Operating AI systems at work isn’t about prompts. It’s about judgment, workflow, and knowing where the seams are. This is the guide I wish I’d had.

Level 1 · Lessons 1 to 6

Knowing your Claude

The groundwork for using Claude well in a plain chat window: when AI is the right call, which model to reach for, and how to ask so you get a usable answer the first time.

  • 1ConceptShould AI do this?Before you pick a model, scan eight quick checks to decide whether AI should touch the task at all, where a single no is enough to stop you.7 min read
  • 2ConceptPick the right modelThe whole picker is two independent dials, tier and effort, so start low and climb one step only when the result shows you it fell short.8 min read
  • 3ConceptWhy you hit your limitA long chat quietly drags its whole history into every turn, so it costs more and gets forgetful, and the fix is a fresh chat with a focused handoff.7 min read
  • 4ConceptGive Claude the right contextClaude only knows what is in front of it in the chat, so your job is to hand it exactly the context the task needs: relevant, not more.5 min read
  • 5ConceptWrite a prompt like a specWrite a prompt as a specification of the finished result, not just a topic, so you get a usable answer on the first try instead of the fourth.5 min read
  • 6ConceptCheck the answerClaude's answers sound fluent and sure whether or not they are right, so before you use one, find the claims it can be checked against and verify the few the task leans on.6 min read

Level 2 · Lessons 7 to 14

Working with Claude

Everyday working habits in the chat app: feeding Claude documents, standing up Projects and memory, shaping outputs, researching with current sources, wiring in connectors, and fixing bad answers.

  • 7ExerciseGive Claude things to readSharing a document only helps if you ask narrow questions answered from the page, check where the answer came from, and strip anything private before you attach it.6 min read
  • 8ExerciseProjects, files, and instructionsA Project lets you write your background and rules once so Claude starts every chat already knowing them, instead of re-explaining yourself each time.5 min read
  • 9ConceptMarkdown and the .md file familyMarkdown is plain text with three light marks for headings, lists, and emphasis, which is why it moves between tools without falling apart.5 min read
  • 10ExerciseMemory and standing instructionsStanding instructions are rules you set for every chat and memory is context Claude learns on its own, and credentials belong in neither.7 min read
  • 11ExerciseOutputs: documents, tables, and pagesAsking for the right shape of output matters as much as the content, so name whether you need a chat reply, a table, a document, or a page.6 min read
  • 12ExerciseResearch and web searchWeb search lets Claude pull current sources, but a citation is only worth as much as the source behind it, so you open and judge it yourself.7 min read
  • 13ExerciseConnectors in regular chatConnecting Claude to an app is worth it only for a named job done with the least access, so default to read-only and review anything it sends or changes.5 min read
  • 14ConceptWhen things go wrongA bad answer has a cause, so you diagnose why it went wrong and fix that cause instead of retrying the same prompt and hoping.9 min read

Level 3 · Lessons 15 to 20

Building with Claude

Stepping out of the chat box into Claude Code: the terminal and Git, safe first sessions, the filesystem as context, tools and untrusted input, reusable skills, and testing a workflow before you trust it.

  • 15BridgeExerciseBridge: the terminal, paths, and GitThe terminal is just how you tell your computer where you are and what to do, and Git gives you an undo you can trust before you ever open Claude Code.8 min read
  • 16ExerciseClaude Code: your first safe sessionClaude Code is safe to start when you keep it in a small practice folder, run a mode that asks before acting, read every proposed change, and lean on Git as your undo.6 min read
  • 17ConceptFilesystem as contextOnce Claude can read your folders, the way you name and arrange files becomes the context, so a clear map lets it find what it needs without you pasting anything.4 min read
  • 18ConceptTools, scripts, MCP, and untrusted inputTools let Claude do exact work like math and actions, but exact is not the same as correct, so keep each tool's reach small and treat anything Claude reads from the outside as untrusted.9 min read
  • 19ExerciseReusable skillsA skill is a small file that captures how you do a repeated task, so once you write it down and test it, Claude stops needing the same thing re-explained every time.6 min read
  • 20ConceptVerification and evalsOne good try lies to you, so build a small deliberate test set and run it against a workflow before you rely on it, making failures show up in testing instead of in real work.7 min read

Level 4 · Lessons 21 to 27

Running Claude as a system

Running Claude as a dependable system: planning and human gates, delegating to subagents, a second-brain vault, safe automation, and a guided build-and-defend lab that puts your hands on every control.

  • 21ConceptPlanning, delegation, and human gatesA big job becomes safe when you break it into steps and place a human approval gate at every point where a wrong move would be costly to undo.6 min read
  • 22ConceptSubagents and orchestrationSplitting work across helper agents buys you parallel effort and clean context, but it costs tokens and coordination, so split only when the job is big enough to earn it.6 min read
  • 23ConceptSecond brain: notes Claude can useA vault of small linked notes turns scattered knowledge into something Claude or anyone can find, because the links do the finding for you.7 min read
  • 24ConceptAutomation and safetyBefore any automation runs unattended it needs six controls in place, a threat model, limits, logs, a working stop, and a recovery plan, and you should be able to say why each one has to exist first.10 min read
  • 25LabExerciseGuided build lab, part 1: plan, restrict, gatePart 1 of the guided build lab: on safe practice data you plan and threat-model one small workflow, scope it to least privilege, and build the human gate into the code's shape, putting your hands on the first three capstone controls.9 min read
  • 26LabExerciseGuided build lab, part 2: log, stop, restorePart 2 of the guided build lab: on the same safe practice workflow you add a privacy-aware log, pull a kill switch deterministically, and run a recovery drill from backup, finishing all six capstone controls by hand before the capstone scores them.8 min read
  • 27ProjectCapstone: build and defend a systemBuild a small AI workflow and defend it: prove with saved evidence that it works for someone other than you, and show it fails safely under a hostile input and a broken step.8 min read

Electives · 5 lessons

Electives

Optional deep dives for specific jobs: sourced research-and-publishing workflows, honestly measuring whether AI pays off, and rolling AI out to a team.

  • Elective 1ConceptPublic workflows: research and publishingPublic work is safe only when you source every material factual claim to a page you opened and pass the draft through a human gate before it ships.8 min read
  • Elective 2ConceptMeasuring AI's impactAn honest AI saving counts the review and cleanup time, not just the fast AI run, then turns the net weekly saving into a payback period kept in one unit.8 min read
  • Elective 3ConceptRolling AI out to a teamA team rollout sticks when you start with a small volunteer pilot on one use case, set data rules and success, stop, and expand thresholds before day one, and decide on evidence by a fixed date.7 min read
  • Elective 4ConceptClaude with spreadsheets and dataClaude is useful on a spreadsheet only when you give it the column meanings and sample rows, check every formula and number it produces, try on a small slice first, and keep sensitive data out.9 min read
  • Elective 5ConceptClaude in the browser and desktop appWhen Claude acts in a browser or on your desktop it takes real actions on real pages and files, so you gate the risky ones for a human, give it the least access it needs, practice on safe targets first, and keep a log you can check.9 min read
